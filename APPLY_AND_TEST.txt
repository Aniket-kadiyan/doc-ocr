What this package adds
----------------------
1. backend/gdt_context.py
   Applies drawing context to already-detected GD&T objects without replacing
   visual evidence. It associates nearby values, resolves shared-glyph ties,
   links datum references, demotes loose characteristic false positives, and
   reports standards observations.

2. backend/test_gdt_context.py
   Pure-logic regression tests for ambiguity resolution, value attachment,
   radius parsing, datum association, confidence demotion, audit evidence,
   and standards consistency.

Governing safety rule
---------------------
Context may resolve an existing ambiguity, attach information, or add a
warning. It may not replace a confident visual detection with a different
symbol. If position and visual evidence disagree, the detection is retained,
downgraded to ambiguous, and given a recorded conflict reason.

Behavior added
--------------
- Distinguishes shared glyphs by valid position/context:
  profile-of-line vs arc length, counterbore vs spotface, circularity vs
  diameter vs all-around, diameter vs spherical diameter, and datum marker
  vs datum feature.
- Parses R, CR and SR values while rejecting Ra, Rc, REF, REV and similar
  false friends.
- Associates only sufficiently close text, preferring text on the right in
  the same row. It does not attach the nearest arbitrary number on the page.
- Preserves drawing units instead of assuming millimetres or inches.
- Links FCF datum references by letter and reports missing datum features as
  unresolved findings rather than silently dropping them.
- Demotes geometric characteristics found outside a frame instead of deleting
  them, retaining their evidence for review.
- Reports standard-family mismatches and retired controls as observations;
  it does not claim overall drawing compliance.

Scope boundary
--------------
This milestone adds standalone contextual logic only. It does NOT invoke the
GD&T pipeline from production page scanning, change auto-balloon results,
add API response fields, or alter UI/review/export behavior.

How to apply
------------
1. Confirm you are on selective-integration and have no unrelated local
   changes that these paths would overwrite.
2. Extract this ZIP into the doc-ocr repository root, preserving paths.
3. Review the two added backend files.
