QTracX Installer I3 - Clean Windows Host Bootstrap
==================================================

Apply this after Installer I2 (database bootstrap). The ZIP contains source
changes only. It contains no commit and does not push anything.

Important branch observation
----------------------------

At packaging time, origin/deployment-readiness still reported commit 2e46558
as its tip. If Installer I2 was pushed to another branch or remote, check out
that branch before extracting this ZIP. I3 expects the I2 database-bootstrap
files to be present.

Apply
-----

1. Check out the branch containing Installer I2.
2. Extract this ZIP into the doc-ocr repository root.
3. Allow it to overwrite the matching installer files.
4. Review:

       git status --short
       git diff --check

What changed
------------

- Adds a PowerShell phase-zero bootstrap that runs before Python exists.
- Detects 64-bit CPython 3.13, Node/npm, optional Git, NVIDIA GPU and MSSQL
  ODBC drivers.
- Selects installed 64-bit ODBC Driver 18 first or Driver 17 when that is what
  the target system has.
- Returns the exact WinGet command and official download page when no supported
  ODBC driver is installed.
- Can install Python, current Node.js LTS, Git and ODBC Driver 18 through
  WinGet in explicit Install mode.
- Creates a production virtual environment and installs the selected CPU/GPU
  requirements rather than assuming an existing .venv.
- Runs npm ci from package-lock.json rather than assuming node_modules exists.
- Supports optional production frontend build after .env.local is generated.
- Supports optional PaddleOCR model warmup/download.
- Adds read-only Plan and Verify modes.
- Never deletes or silently recreates an existing environment.

Safe test on the current GPU development machine
------------------------------------------------

From the repository root in PowerShell:

    Set-ExecutionPolicy -Scope Process Bypass

    .\installer\bootstrap.ps1 `
        -Mode Plan `
        -Runtime gpu `
        -Database mssql `
        -EnvironmentDir backend\.venv-gpu

This command makes no changes. On the previously reported development host it
should select:

    ODBC Driver 17 for SQL Server

It should not propose installing Driver 18 when the 64-bit Driver 17 is
detected.

Read-only verification of the existing environment:

    .\installer\bootstrap.ps1 `
        -Mode Verify `
        -Runtime gpu `
        -Database mssql `
        -EnvironmentDir backend\.venv-gpu

Do not use Install mode merely to test an already configured development
machine. The complete Install path should later be tested in Windows Sandbox
or a disposable Windows 11 VM.

    Pop-Location

Fresh-host installation command
-------------------------------

After source acquisition and after the deployment .env.local has been
generated:

    .\installer\bootstrap.ps1 `
        -Mode Install `
        -Runtime cpu `
        -Database mssql `
        -BuildFrontend `
        -WarmModels

Use -Runtime gpu only when an NVIDIA GPU and suitable driver are detected.
GPU mode is not silently downgraded to CPU mode.

Licensing note
--------------

The Python/Node application dependencies remain under the previously reviewed
permissive licenses. Microsoft ODBC Driver itself is a proprietary Microsoft
redistributable, not an MIT/BSD/Apache library. It is required only for MSSQL;
PostgreSQL uses the BSD-licensed pg8000 driver.
