--------------------------

2. Confirm your current branch contains the M6 base:
     git merge-base --is-ancestor 7fab455 HEAD
     if ($LASTEXITCODE -ne 0) { throw "M6 base 7fab455 is missing" }

     git status --short
4. Extract this ZIP over the doc-ocr repository root, preserving folders.
   It is safe to paste directly over the earlier flawed M7 package; reverting
   that package first is not required.
5. Review the result:
     git status --short
     git diff --check

Expected M7R1 behavior
----------------------
- A usable vector PDF text layer remains authoritative for the whole page or
  selected section. The presence of a possible frame, datum, or surface mark
  no longer launches full-page raster OCR.
- Exact native text and bounding boxes are preserved. OCR/geometry may attach
  structured evidence on fallback/hybrid paths, but cannot replace native text.
- Feature-control frames, boxed datum letters, and surface-finish evidence are
  detected from pixels and combined with OCR text.
- Complete geometry-backed objects can become balloons.
- Unresolved feature-control symbols remain visible in Review.
- Text-only GD&T is never auto-accepted without matching frame geometry.
- A lone horizontal stroke cannot manufacture a straightness symbol, and large
  nearby drawing diagonals cannot relabel an ordinary dimension as a surface
  finish value.
- Every absorbed OCR fragment remains in assembly_children.
- Structured evidence persists in projects, review candidates, and backend
  checksheet revisions.
- Existing diameter, degree, plus/minus, M4 assembly, M5 parsing, and M6
  Review/Other accounting remain active.

Suggested commit message
------------------------
fix(ocr): preserve native PDF text during symbol detection
