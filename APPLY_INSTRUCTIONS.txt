Optional HTTPS
--------------
To request HTTPS for both the UI and backend, add a PEM certificate and its
unencrypted PEM private key on the server, then configure:

   HTTPS_ENABLED=true
   TLS_CERT_FILE=certificates/qtracx-cert.pem
   TLS_KEY_FILE=certificates/qtracx-key.pem

Relative certificate paths are resolved from the repository root. Absolute
paths are also accepted. Restart both processes after changing these values.

Both launchers validate the certificate/key pair. If the flag is false, or if
either configured file is missing, unreadable, invalid, or mismatched, QTracX
uses HTTP. When HTTPS was requested but cannot activate, a warning explains the
fallback. There is no HTTP-to-HTTPS redirect.

The backend CORS policy intentionally accepts all browser origins because the
client LAN hostnames, IP addresses, and ports are unknown. Credentialed requests
remain supported, and application authentication plus CSRF checks remain active.

Verification
------------
From the repository root:

   npm run typecheck
   npm run lint
   npm run test:frontend
   npm run test:runtime
   npm run build

From backend, using the project's configured CPU or GPU virtual environment:

   python -m pytest -q test_config_env.py test_transport_security.py `
     test_cors_config.py test_auth_routes.py

After starting the backend, GET /health. The transport object reports:

   https_requested  - whether HTTPS_ENABLED requested TLS
   https_active     - whether a valid certificate pair activated TLS
   scheme           - http or https
   http_fallback    - true when requested HTTPS fell back to HTTP
   fallback_reason  - a non-secret explanation when fallback occurred

The same response reports cors.policy as allow_all_origins.
